## Staleness hunt
A kernels / portable row counts as stale when `git log` shows a performance-relevant commit of its family, `shared/`, `_optimize` or `_core` after the row's date (docs- and test-only commits ignored). Re-measured (162 ref x mode): the previous worker's skipped list (SEA-RAFT x7 + RAFT x4 [3284e0d0], tipsv2 / waft-stereo / unidepth-v2 / vggt [4c514873 shared DINOv2 blocks], vitpose portable [8b72fab0], SeedVR2-7B [5283f796]) plus the families hit by the memory / shared commits: convnext + convnextv2 + the classification refs (deit, swin, tiny-vit, falconsai; 956ea9ea / 9e927861 fold changes), da3 x5, dinov3 x4, c-radio, detection (rf-detr, rtmdet, yolox, deim, dfine), pose (rtmpose, rtmw, dwpose, hrnet, rf-detr-keypoint).
Not re-measured: rows only flagged through the broad `_optimize` / `_core` dependency whose own code is unchanged and whose row is not older than the commit (clip / siglip / pe rows are newer than their commits), the stereo / matting / segmentation families already re-measured on 2026-11-16 (`remeasure.md`), and compile / tensorrt rows (not touched).

Slower by more than 3 % or more memory, one by one:
- convnext portable 224 (12 cls + 4 features refs): +3.1 .. +5.7 %, alloc -45 .. -180 MB. Launch-bound (wall 3.3 ms vs 0.96 ms GPU kernel time), the deliberate memory-for-latency step of 9e927861 / 956ea9ea (folded fc2 + addcmul path in `_optimize/transformer.py`, fewer live tensors). A fold experiment to win the time back changed numerics / memory and was reverted; patch kept out of the tree. Kernels rows are -0.3 .. +0.5 %. Accepted: memory down 25-30 %, GPU time unchanged.
- dinov3 (real regression, fixed): kernels ViT-L reserved 812 vs 652 before, H+ portable 1968 vs 1668 before, ViT-S/B/L portable +20..26 reserved. Root cause: the 792ca734 device build (fp32 load, fold / cast / pack) interleaves transient fp32 and final fp16 allocations, which leaves 2 MB holes inside 20 MB allocator segments that `empty_cache` cannot return. Fix `a9d7860e`: `shared/arena.py::compact` packs every CUDA parameter / buffer of the built model into one 512-byte-aligned arena per (device, dtype), ties stay shared; used in the dinov3 `_network`. General test `tests/test_arena.py` (storage, alignment, ties, no reserved holes after the build). Result: kernels L 812 -> 650, H+ portable 1968 -> 1666, H+ kernels 1672, ViT-B kernels 210; alloc unchanged. The remaining +20..26 MB reserved on portable ViT-S/B/L (78 -> 104, 206 -> 226, 626 -> 646) is the cuDNN / cuBLAS workspace of the first call, which used to land in the holes; an `empty_cache` after `compact` does not change it (tested, reverted). Peak alloc is identical, so accepted as the workspace now showing as its own segment. Other families that build through a fp32 device load (INSID3, the track-on copy of the dinov3 net) may have the same holes: not checked.
- raft-large-kitti kernels 375x1242: 21.00 -> 21.77 ms (+3.7 %, repeated twice, 21.73 / 21.77), 1080x1920 +0.5 %, alloc -2, reserved 112 -> 92. Not the in-place correlation scale of 3284e0d0 (A/B with the out-of-place divide: 21.72 ms); the old row (2026-11-09) predates three api commits and the launch-bound 375x1242 shape is the only one affected. Unexplained, left; it is below the 5 % budget of the speed floor and memory is down.
- da3-large-1.1 kernels 518x770: +1.3 %, alloc +49, reserved -60 (repeated: 16.87 / 16.96 ms). Allocation split moved between segments after the shared-block change; reserved (what the GPU holds) is down, kept.
- rtmpose-l portable 1080x1920: +1.3 %, reserved 236 -> 256 MB, alloc -11 (repeat identical 9.04 / 9.05 ms); cudnn conv workspace segment, same cause as the dinov3 leftover. Kept.
No other row slower than 3 % or with more memory.

## Cross-family float16 stress scan (`tools/fp16_stress.py`, new)
Default model of every restoration / depth / segmentation / matting / edges family (59 models), portable and kernels fp16, on noise, low-contrast noise (0.5 +- 0.05), constant 0, constant 1, constant 0.5 and saturated 0 / 1 images via the task's `bench_inputs`: 648 (model, mode, input) cases, raw `fp16_stress/stress_*.jsonl`.
Found: 1 non-finite output, u2net portable on a black image (NaN alpha): `x / x.amax()` divided 0 by 0 (upstream does the same). Fixed at the root in `e2a2a4d0` for all four min-max-normalising matting runners (u2net `/ max` + min-max, isnet, ben2; inspyrenet already had `+ 1e-8`): the divisors are floored at 1e-8 (no change for any non-constant input). General test `tests/test_matting_stress.py` (slow, CPU, random weights: black / white / grey image finite; fails without the fix for u2netp). Re-scan of matting: 72 / 72 ok. Everything else finite in both modes: restoration, depth, segmentation, edges: none.
Not covered (no 3-channel image input or not an image-to-map task): flow / stereo / multiview pairs, detection / pose boxes, features, classification; fp16 there is exercised by the golden and family-smoke tests.
