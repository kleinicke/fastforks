Method for (a)-(c): per ref and tested size, latest row per mode; "original" = strictest of the upstream / upstream-default rows (fastest ms, lowest peak). Memory flagged only when > 1 % AND > 16 MB (allocator granularity). Classification: "explained" = within 3 % time / 3 % + 64 MB memory (kernels vs portable memory: 5 % + 64 MB); everything beyond is "needs optimisation or re-measure", listed in `needs_attention.txt` (135 refs, with family and the action). Caveat: original rows come from older harness runs at partly other dates; a re-measure of the original at the same time may remove a part of them.

## Per check

(a)-(c): full list `speed_compare_all.csv` (every ref x size with all numbers and flags), `a_memory_above_original.csv`, `b_slower_than_original.csv`, `c_kernels_worse_than_portable.csv`, classified in `findings_speed.csv`. Notable explained or known: `squeezenet1_1` portable memory 41 vs 10 MB (torch CUDA context-level floor, tiny model); the gap is a fixed ~30 MB; `pspnet-r101-d8-ade20k`, `moge-3-vitl`, `gmflow`, `rife` are slower by < 7 % while using 25-75 % less memory. Slower families that need optimisation (the slowdown is > 3 % at the tested size): `flowformer-small-*` (-14 %, also +33 % memory at 375x1242), `neuflow-v2*` (-16 %), `film` (-8..12 %, +54..61 % memory), `efficientvit_b2` (-10 %), `fastvit_t8`, `dinov3-convnext-tiny` (kernels are faster there), `moge-3-vitl`, `gmflow-scale1-*`.

(d): flagged rows: `anycalib-pinhole` portable + kernels vfov_auc1 24.0 vs 24.5 (0.5 point on n=200, a fp16 AUC step; explained), `flowseek-t` portable epe 1.348 vs 1.260 on KITTI-2015 n=200 (fp16; upstream's own autocast fp16 gives 1.360: explained as fp16 effect, kernels row is within 2 %), `waft-a1` 2.315 vs 2.395 (better), `vggt-omega-1b-512` DTU absrel 0.0051 vs 0.0050 (2.0 %, rounding at 4 digits), `s2m2-l` ETH3D bad 0.82 vs 0.84 (better), `loftr-outdoor` (open, above). Accuracy cards with a per-card tolerance statement were not used as the threshold (flat 2 % applied).

(e): 24 are original fp32 / default OOM (by design). The other 51 are all documented non-chosen or non-shown rows: `upstreamhalf` / `upstream-fp16` / `upstream16` tiers of the original that crash or give non-finite output in fp16 (the README says fp16 originals are shown as measured; failing `.half()` tiers are not shown, `column = null`) = 48 rows in stereo/depth/multiview; `portable32` OOM at Middlebury (1 row, fp32 does not fit 16 GB). Speed rows: portable OOM `flowformer-small-{chairs,things,sintel}` at 1080x1920 and kernels + portable `seedvr2-7b` at 512x512 (16 GB device; the card states the memory limit; the 7B was tested with the new `stream=True` default on 2026-11-15, re-measure of these two rows with streaming is in the queue below). No NaN in any row.
